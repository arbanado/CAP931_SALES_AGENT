# 📊 CAP 931 – Multi-Agent GPT Sales Assistant

## Project Overview

This project was developed for **CAP 931: Capstone – Build a Sales Agent Prototype Using Multi-Agent GPT Models**.

The Sales Assistant Agent is a Python and Streamlit application designed to help sales representatives research prospective customer accounts and prepare for sales opportunities.

The application uses a **multi-agent LLM architecture** to analyze company strategy, competitors, leadership information, product fit, risks, and potential sales opportunities.

The results from the specialized agents are combined into a concise **Sales Account One-Pager** that can be reviewed and downloaded by the sales representative.

---

## 🎯 Project Objectives

The main objectives of this project are to:

- Build a functional AI-powered sales assistant prototype.
- Use an OpenAI GPT model for sales intelligence and analysis.
- Implement a multi-agent architecture.
- Research prospective companies and their business strategies.
- Analyze competitors relevant to the sales opportunity.
- Identify relevant leadership and decision-makers.
- Support optional product-document PDF uploads.
- Apply prompt-engineering techniques to improve output quality.
- Generate a structured Sales Account One-Pager.
- Provide source information for research findings.
- Allow the final report to be downloaded from Streamlit.

---

## 🏗️ Multi-Agent Architecture

The application divides the research process among specialized AI agents.

### Agent 1 – Company Research Agent

Researches the prospective company and identifies information such as:

- Company strategy
- Relevant business initiatives
- Recent developments
- Technology direction
- Potential product alignment
- Publicly available business information

### Agent 2 – Competitor Research Agent

Analyzes competitor information provided by the user and evaluates:

- Competitive positioning
- Competitor relevance
- Potential competitive risks
- Sales implications
- Differentiation opportunities

### Agent 3 – Leadership Research Agent

Identifies leadership information relevant to the sales opportunity, including:

- Key executives
- Relevant decision-makers
- Leadership roles
- Public leadership statements
- Potential stakeholders

### Agent 4 – Final Report Agent

Combines the outputs generated by the research agents and creates an executive-level **Sales Account One-Pager**.

The final report can include:

- Executive Snapshot
- Company Strategy
- Competitive Landscape
- Key Decision Makers
- Product Fit
- Recommended Sales Approach
- Key Risks
- Sources

## 🧠 Model Selection

The prototype uses an **OpenAI GPT model through the OpenAI API**.

The model was selected because the application requires:

- Natural-language understanding
- Business information analysis
- Prompt instruction following
- Information synthesis
- Structured output generation
- Sales-oriented recommendations

### Model Advantages

- Strong natural-language capabilities
- Effective structured report generation
- Good prompt-following ability
- Fast API integration
- Suitable for multi-agent workflows

### Model Limitations

Large Language Models can occasionally generate inaccurate, incomplete, or unsupported information.

To reduce this risk, the prompts instruct the agents to:

- Avoid inventing unsupported facts.
- Distinguish facts from recommendations.
- Preserve useful source information.
- Avoid inventing executives or business relationships.
- Focus only on information relevant to the sales use case.

## ✍️ Prompt Engineering

Several prompt-engineering techniques were applied during development.

### Basic Prompt

The initial approach used broad company-research instructions.

This produced useful information but sometimes generated responses that were too general or lengthy.

### Structured Prompt

The prompts were improved by specifying required sections and expected output.

This increased consistency and relevance.

### Role-Based Prompting

Each agent was assigned a specific role:

- Company researcher
- Competitor analyst
- Leadership researcher
- Final report writer

This helped each agent concentrate on a narrower task.

### Prompt Chaining

Outputs from the specialized agents are passed to the Final Report Agent.

```text
Company Research ────────┐
                         │
Competitor Research ─────┼──► Final Report Agent
                         │             │
Leadership Research ─────┘             ▼
                              Sales Account One-Pager
```

### Output Constraints

The final report prompt uses constraints designed to:

- Reduce unnecessary verbosity
- Avoid repetition
- Use professional business language
- Separate facts from recommendations
- Preserve sources
- Produce a concise executive report

## 🧪 Prompt Engineering Experiments

| Experiment | Approach                    | Result                            |
| ---------- | --------------------------- | --------------------------------- |
| 1          | General research prompt     | Useful but broad output           |
| 2          | Structured prompt           | Better organization and relevance |
| 3          | Role-based prompting        | More specialized analysis         |
| 4          | Multi-agent prompt chaining | Better overall research synthesis |
| 5          | Constrained final report    | More concise executive output     |

The multi-agent structured approach produced the most useful results for the sales-assistant use case.

## ⚠️ Challenges and Solutions

| Challenge                                        | Solution                                                               |
| ------------------------------------------------ | ---------------------------------------------------------------------- |
| Git was initially unavailable in VS Code         | Git was installed and configured                                       |
| OpenAI credentials were not initially detected   | Environment variables were configured using `.env` and `python-dotenv` |
| `.env` was initially created incorrectly         | It was corrected and recreated as a file                               |
| Protecting the API key                           | `.env` was excluded through `.gitignore`                               |
| Streamlit could not initially access the API key | Environment loading from the project root was configured               |
| Competitor variable error                        | Competitor URL processing and variable names were corrected            |
| LLM responses could be too broad                 | More specific role-based prompts were implemented                      |
| Need for product-document processing             | A PDF parser was added                                                 |
| Final report could become too long               | Output constraints and one-page formatting were introduced             |
| Need to save generated results                   | A Streamlit download feature was added                                 |

## 🚀 Installation

Clone the repository:

```bash
git clone https://github.com/arbanado/CAP931_SALES_AGENT.git
```

Move into the project directory:

```bash
cd CAP931_SALES_AGENT
```

Install the project dependencies with UV:

```bash
uv sync
```

---

## 🔑 OpenAI API Configuration

Create a `.env` file in the project root.

Add:

```text
OPENAI_API_KEY=your_openai_api_key
```

**Never upload the `.env` file or API key to GitHub.**

The project's `.gitignore` is configured to exclude sensitive environment files.

---

## ▶️ Running the Application

Run the Streamlit application with:

```bash
uv run streamlit run src/app.py
```

Streamlit should start the application locally.

The default local address is typically:

```text
http://localhost:8501
```

## Conclusion

The CAP 931 Sales Assistant Agent demonstrates how Large Language Models can be combined with prompt engineering, multi-agent architecture, document processing, and a Streamlit interface to support sales research.

Instead of relying on a single general-purpose prompt, the application separates company research, competitor analysis, leadership research, and final report generation into specialized components.

The resulting prototype provides sales representatives with a structured method for transforming account information into actionable sales intelligence and an executive-level Sales Account One-Pager.
